# V3.1 — v3 GRPO: reward, recipe, pre-registration and Kaggle runner

**Wave 7 (v3, OWNER D-66). Depends on:** R4.5. **Unblocks:** V3.2 (the trial and main GRPO runs, selection and freeze), then V3.3 (export, parity, the one scoring run and the release).

## Goal
Get everything that decides v3 fixed, tested and hashed before any GPU step: a programmatic reward that pays for a correct label and grounded citations and penalises citing the study's aim sentence (the v1 failure), proven against planted reward hacks; a GRPO recipe that continues v2's own adapter; the pre-registered metric, test set, judge, decision rule and dev selection rule; and a pinned Kaggle notebook that the portfolio-site session pushes (OWNER D-66).

## Design
- **Reward (RLR-01, RLR-02).** `src/ggh/rl/reward.py`: EvalKit's own answer parser; +1 for the gold label, +0.5 more when that right answer's citations are grounded (a wrong label earns nothing for its citations, so the reward's best reply is the most likely label, with no premium for yes/no over "maybe"), −0.5 for a yes/no answer citing an aim sentence (TGT-R12), −1 when unparsed. "Grounded" is stricter than an index range check because the plan's hacks pass a range check: for every label 1–3 distinct in-range citations and an answer of 6–80 words; for yes/no also no aim or method sentence and ≥ 2 content words shared with each cited sentence; "maybe" is grounded only for a "maybe" gold label. Planted hacks (all-"maybe", aim citation, citing everything, terse or empty answers, valid-but-unrelated citations) each earn less than an honest policy with a third of its labels wrong. On v2's own 2,722 gold targets 98 % earn the maximum; on v2's 500 dev replies the mean is 1.35 of 1.5 (82 % at the maximum), so headroom is small (recorded in known issues).
- **Recipe (RLR-03).** `configs/recipe_v3_grpo.yaml` continues v2's adapter (Hub `biplob123/gemma-4-e2b-grounded-health` at tag v2.0.0, `adapter/`, checked against TrainRun v2's hash); base, revision, LoRA shape and dtype come from `configs/recipe_v2.yaml`. 8 completions per prompt, 4 prompts per optimizer step, learning rate 5e-6, no KL term (with PEFT, TRL's reference model is the adapter-free base, not v2), TRL's loss settings pinned (dapo, group scaling, epsilon 0.2, one iteration), one epoch; every trainer argument is checked against the field lists of TRL 1.15 and transformers 5.17.
- **Trainer and logging (RLR-04).** `ggh grpo` (TRL 1.15 `GRPOTrainer` under Unsloth) logs the reward by component (parse, label, grounded, aim; they sum to the reward) plus zero-weight probes for the "maybe" share and answer length, so a hack shows in the log.
- **Dev check (RLR-05).** `ggh rl-dev` scores v2 and each checkpoint, greedy, on dev prompts with the reward and the hack signals.
- **Kaggle runner (RLR-06).** `ggh.rl.notebook` renders a thin notebook pinned to a commit on origin/main (trial: 40 steps and 200 dev prompts; main: full run and 500).
- **Pre-registration (RLR-07).** `configs/eval_plan_v3.yaml`, hashed in `docs/measurements/eval_plan_v3.sha256` before any training: primary v3 − v2 headline (above 0.329 with the paired interval excluding zero), guardrails citation precision ≥ 0.70 and aim-citation rate ≤ 0.10, stretch 0.404, the dev selection rule with hack guards, one scoring run on the same 1,000 PQA-L cases with GPT-6.1 Sol and GPT-6 Luna (OpenAI only), and the reward, trainer, target rules, recipe schema, recipe and Kaggle packages pinned by hash; selection guards on the maybe, yes and no-recall shares as well as parse failures, length, accuracy and aim citations; numeric stop rules for the trial.
