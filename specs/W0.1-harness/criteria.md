# W0.1 acceptance criteria

One block per capability. Each criterion is checked by a named test.

**HAR-01 — uv project and package skeleton**
- `uv sync` succeeds; a `Makefile` offers `check`, `status`, `converge` and `selftest`; `ggh doctor` lists which credentials are set by name only, never a value; `ggh --version` prints `ggh 0.0.1`, matching `pyproject.toml` and `ggh.__version__`.
- `pyproject.toml` names the distribution `gemma-grounded-health`, requires Python ≥3.11, declares Apache-2.0 with `LICENSE` and `NOTICE` as licence files, and the `ggh` console script.
- `LICENSE` is the Apache-2.0 text; `NOTICE` credits Gemma 4 and PubMedQA; `.pre-commit-config.yaml` runs ruff and the secret scan; `.gitattributes` forces LF (EK-L-7).

**HAR-02 — CI**
- `ci.yml` runs on push to main and on pull requests with `contents: read` only and no secrets; runs ruff check, ruff format check, pyright, pytest, the secret scan, the graph check, the converge self-test and `uv build`; matrix is ubuntu-latest and macos-latest × Python 3.11 and 3.12.

**HAR-03 — graph eligibility**
- Fails on a cycle, an unknown dependency, an unparseable `depends_on`, a catalog row naming an unknown node, a node building or starting ahead of a non-green dependency, and a node id outside `[WNTEXRPO]`.
- Passes on the live graph. `--self-test` passes.

**HAR-04 — node start**
- Refuses when the node is unknown, has no catalog rows, a dependency is not green, the spec folder or any of `spec.md`, `criteria.md`, `tasks.md` is missing, or `criteria.md` misses a capability. Check-only runs write nothing; `--mark-building` writes `.base` once and flips rows. `--self-test` passes.

**HAR-05 — node converge**
- Runs the 13 gates in the documented order (claims-work, eligibility, proofs, ruff, pyright, pytest, golden, data, recipe, safety, build, changed-tests, records) and reports every one even after a failure; exits 1 if any gate fails; writes a log under `.harness/<node>/`.
- Under D-29, `--self-test` shows every gate failing on a planted defect and asserts the defect's text in the gate's detail (EK-L-4, L-1), with a PASS case where meaningful, calling the real gate function for every one of the 13 gates and covering every defect a W0.1 verifier demonstrated (including `gate_changed_tests` on a git repo with committed and untracked changes, `gate_records` for each missing record, and `gate_build` through its default smoke list) and the gate runner itself; golden, data, recipe, and changed-tests outside git report SKIP, not PASS. Smoke commands are exactly `ggh --version`, `ggh --help`, `ggh doctor`, and a failing smoke command fails gate 11. The runner reports every gate after a failure and counts a crashing gate (any `Exception`, or a `SystemExit`, even one whose repr fails, raises `SystemExit`, or returns a str subclass that misbehaves) and a gate returning anything but an exact `Result` whose status is an exact `str` equal to PASS, FAIL or SKIP and whose detail is an exact `str` as FAIL, and still reports the gates after it; `converge()` returns 1 when any gate fails and 0 otherwise. `converge()` writes the log before printing, logs every run through `write_log`, which creates logs exclusively and writes undecodable text escaped rather than crashing, and prints the report escaped so a strict UTF-8 console cannot crash it (self-tested against a strict console), so concurrent or same-second runs never overwrite each other (self-tested with 32 writers released together). The tiny-package build checks need the build backend from the uv cache or PyPI; when an independent probe build cannot get it, they print a visible skip instead of failing.

**HAR-06 — records**
- `graph.md` parses to 18 nodes with no cycle, and its node ids, titles and dependencies equal Tech Spec §13.2; inside a `Node` table every first cell must be a canonical ASCII node id (no leading zeros, no Unicode digits, never empty), so near-miss ids (`WW1.1`, `N1.1a`, `N11`, `N1.1.1`, `W0-1`, `N1.01`, full-width letters) are rejected, not skipped, and duplicate dependencies are rejected; `catalog.tsv` holds 113 rows whose cap ids and nodes equal Tech Spec §13.4, read as an independent list (EK-L-10); every node has rows.
- `decisions.md` holds D-1 to D-31, each row equal to Tech Spec §1, with OWNER on 15, 17, 23–27; the public PRD carries no application framing and the original is gitignored (OWNER D-26); `lessons.md` holds the 16 EvalKit lessons of Tech Spec Appendix B plus this project's own; `.gitignore` ignores top-level `results/` but not `docs/results/`; `changelog.md` has a `[W0.1]` entry; `status.py` prints the graph table, a per-node table and the ledger totals, deterministically.

**HAR-07 — secret scan (a heuristic backstop, D-30)**
The scanner is pattern-based, so this criterion lists exactly what it must catch and must not flag; GitHub secret scanning and push protection on the public repo are the backstop for everything else (D-30). Each listed form has a test.
- **Token formats caught:** Anthropic (`sk-ant-…`), OpenAI (`sk-…`, `sk-proj-…`), AWS access (`AKIA…`/`ASIA…`) and secret keys, GitHub (`ghp_…` etc., `github_pat_…`), PyPI (`pypi-…`), Hugging Face (`hf_…`), Kaggle API tokens (`KGAT_…`), and PEM private keys.
- **Token boundaries:** a token is caught when glued to other text (`x_hf_…`, `x_sk-…`, `AKIA…_x`, `x_KGAT_…`) or when it follows a JSON escape (`\n \t \r \b \f \uXXXX`).
- **Kaggle keys:** `KAGGLE_KEY` followed by a 32-hex value is caught when the value sits within 60 characters on the same line (including directly after it) (env, `export`, quoted, `os.environ[...] =`, `setdefault`/`get` with or without `value=`/`default=`, typed `: str =`/`: Final =`), or within 80 characters and 1 to 3 line breaks across lines (a value on the same line is judged only by the 60-character rule) (backslash-continued, parenthesised, with a comment in between, setdefault spread over lines). Each `KAGGLE_KEY` occurrence is tried on its own, so a match at one occurrence never stops a different occurrence from being matched. `kaggle.json` objects (`username` plus a 32-hex `key` in either case, either order, single or double quotes) are caught compact, pretty-printed, JSON-escaped, or both pretty-printed and escaped (inside a string, or in a notebook's raw JSON across source lines).
- **Notebooks:** a notebook that parses as JSON is scanned as decoded text, never as raw JSON lines. Per cell: the joined source, each output's joined stream text and traceback lines (joined with line breaks), and each textual mime value (including `image/svg+xml`) as the user sees them; then everything else in the cell, rendered as indented JSON so every key stays on the same line as its value (cell and output metadata, JSON-valued mime types such as `application/json` whether object or array, `ename`/`evalue`, attachments). The rest of the document (notebook metadata, papermill parameters, widget state) is rendered the same way. Hits name the cell (`:cellN:`) or `:meta:`; each part is judged separately, so an allow marker in one part never hides a secret elsewhere, and the 60-character and 3-break limits apply to the decoded text. Parity: for each listed placement in the tests, the decoded scan catches what a raw scan of the same notebook catches. A cell's source is also scanned together with everything it printed (every output's stream text, traceback, textual result and error `evalue`, blank lines kept), so a value printed after reading `KAGGLE_KEY` is caught. A notebook with duplicate JSON keys is scanned raw. Mime types match case-insensitively. A notebook that does not parse, or any part of which cannot be rendered (for example nesting too deep), is scanned raw as a whole, never with parts dropped; a malformed notebook (wrong types, null cells, deep nesting, BOM) never crashes the scan.
- **Reporting (D-31):** the contract is detection. Every listed form yields at least one hit naming its file, and for a decoded notebook its cell (`:cellN:`) or `:meta:`. How many hits a file or cell gets is best-effort and not part of the contract: one secret seen in overlapping parts is usually reported once, and distinct secrets usually separately.
- **Not flagged:** a bare or nested `"key": <32 hex>` cache key, even next to a `username` field; a 32-hex value more than 3 line breaks after `KAGGLE_KEY`, or more than 60 characters after it on the same line; ordinary repo content (the live repo is clean). Known false positive, documented in the code: an object of exactly `username` and a 32-hex `key`.
- Honours the `secret-scan: allow` marker only on the lines of the match it sits on (a marker on another line never hides a secret); lines are counted on `\n` only, so form feeds, U+2028 or NEL earlier in a file cannot shift that window; skips model and data binaries (gguf, safetensors, bin, parquet, pt, pth, ckpt, onnx, arrow, npy, npz, h5, pkl, tar). Outside git, the fallback skips tool caches and `.venv*` folders anywhere, `dist`, `build`, `artifacts`, `venv` and `env` only at the top level (so `src/env/` is scanned), and any directory holding `pyvenv.cfg`.
- GitHub secret scanning and push protection are enabled on `biplob819/gemma-grounded-health`.

**HAR-08 — ledgers**
- `ggh.ledger.append` writes one sorted-key JSON line with `at`, `kind` and exactly one of `spent_usd` or `gpu_hours`; it rejects NaN, infinite, negative, boolean, non-numeric or overflowing amounts (including integers past Python's digit limit), an empty or non-string kind, reserved extra fields, and extras that are not plain JSON (NaN, objects, absurd nesting); it validates everything before creating any directory and stores -0.0 as 0.0 (EK-L-12). `str` and `Path` paths are both accepted.
- `ggh.ledger.total` and `count` return 0.0 / 0 for a missing file; `total` sums with `math.fsum`. Both raise `LedgerError` for each of these listed path and line-structure cases, each with a test: a malformed or non-object line, duplicate keys, both amount fields on a line, absurd nesting, invalid UTF-8, a directory or FIFO in place of the file, a parent path that is a file, a broken or looping symlink (as the file or as any parent directory), an unreadable file or directory, an over-long path, and a NUL byte in the path. `total` also raises `LedgerError` for a bad stored amount, a stored integer past the digit limit, and an overflowing total (`count` only counts entries). `append` raises `LedgerError` for an unwritable target, a FIFO, a parent that is a file, an over-long path (a component over 255 bytes is rejected before any directory is made) and a NUL byte, and a failed append leaves no directory behind. Lines are split on `\n` only, so U+2028 or NEL inside a JSON string is valid.
- `status.py` shows both totals computed by `ggh.ledger.total` (one implementation, L-2); a `LedgerError` prints `Ledgers — ERROR: …` and exits 1, never a `nan`, negative or silently zero total.
