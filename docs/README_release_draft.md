> **Research only, not medical advice.** The model summarises what a study abstract says. It is not guidance for anyone's diagnosis or treatment.

A small open model (Gemma 4 E2B, fine-tuned with LoRA) that answers a biomedical research question **only from the abstract you give it**, as JSON with a yes, no or maybe label, a short answer and the numbers of the sentences it relied on. It is scored with [EvalKit](https://github.com/biplob819/evalkit) against its own base model and two API models, and it runs offline on a laptop.

## Results

<!-- ggh:results:start (generated by `ggh readme-table`; do not edit) -->
On 1000 expert-labelled PubMedQA questions (EvalKit run `r-f0f3b432a413`, judges: dual, calibration: uncalibrated); 95% intervals in square brackets:

| Model | Accuracy | Correct and grounded (claude-opus-5-5) | Correct and grounded (gpt-6.1-sol) |
|---|---|---|---|
| gemma-e2b-base-q4 | 0.501 [0.469, 0.532] | 0.418 [0.387, 0.448] | 0.394 [0.364, 0.424] |
| **gemma-e2b-grounded-q4** | 0.728 [0.700, 0.755] | 0.388 [0.358, 0.419] | 0.330 [0.301, 0.359] |
| claude-haiku-5-5 | 0.685 [0.656, 0.714] | 0.345 [0.316, 0.374] | 0.231 [0.205, 0.257] |
| gpt-6-luna | 0.579 [0.548, 0.611] | 0.431 [0.401, 0.462] | 0.290 [0.262, 0.319] |

Caveats: judge not calibrated for this task (see docs/calibrate-your-task.md). The demo runs bf16 weights; the benchmark scores Q4_K_M, which agrees with bf16 on the label for 0.956 of 500 dev prompts. On a laptop (Apple M3 Max) the Q4_K_M GGUF generates 105.1 tokens/s (p50). ## Try it

![The Space: base and fine-tuned answers side by side, cited sentences highlighted](docs/assets/screenshot-space.png)

- **Space:** six sample questions work without a passcode. Live answers on your own abstract need the demo passcode; bringing your own Anthropic or OpenAI key for the grounding check does not replace it.
- **Offline with Ollama:**

  ```bash
  ollama run hf.co/<owner>/gemma-4-e2b-grounded-health-GGUF:Q4_K_M
  ```

- **Offline with llama.cpp:** `uv run ggh llama fetch && uv run ggh serve --model ft` and send EvalKit's PubMedQA prompt to `http://127.0.0.1:8081/v1/chat/completions`.
- **The demo locally:** `uv run --with gradio ggh space --local` against `ggh serve`.

## Reproduce from scratch

Step by step in [docs/reproduce.md](docs/reproduce.md) (R4.5): data, targets and audit, training on Kaggle, export and parity, the laptop benchmark, the EvalKit runs, the results bundle, the model card and the release dry run.

```bash
uv sync
uv run ggh data && uv run --group nli ggh targets
# training runs on Kaggle (notebooks/train_kaggle.ipynb); then export, parity, bench, eval
uv run ggh card && uv run ggh readme-table --write README.md
make release   # dry run: lists every file for the two Hub repos and checks lineage and sha256s
```
